Three suites under three GearSwap versions

Six characters fight one Dynamis Divergence wave inside an 18-player alliance: a Bard, a Geomancer, a White Mage, a Corsair, a Blue Mage and a Warrior. Three GearSwap suites run that fight on the same gear, as in the three-suite report. That report found GearSwap's own work to be most of every suite's cost. This document takes the report's headline sections and sets the three suites side by side under three versions of GearSwap. The suites' own code is the same measurement under every version. Only GearSwap's own work changes, priced from a counting session Rahvin played in the game on each version.

    Written by Rahvin, the developer of Rahvin GS. The suite began as a fork of Mirdain's include and took its own name when it was split into components. Of the three engines here, only Rahvin GS is the author's own. Mirdain 1.5.12 is the original include as Mirdain shipped it. Selindrile is a third author's suite, measured at its upstream commit of 2026-07-23. Rahvin GS 2.1 is measured as it ships, at its release commit (GearSwap 0f8350e, 2026-09-24), with its engine, gear library and job files together. Every feature claim was read from each suite's source rather than its documentation. Every charted figure comes from the measurement run unedited. Of the GearSwap versions set side by side here, GearswapRevised is the author's own: his fork of GearSwap 0.940, meant for players to use in place of GearSwap's Live and Dev versions.

      Cause 1

      GearSwap's refresh

      Before GearSwap hands an event to a job file, it refreshes its picture of the player, the world and the party.

      A refresh comes in two sizes. A full one also rebuilds the character's own record. GearSwap runs a full refresh before each action the player types, again when the action completes, and for every buff packet that changes a buff, every status change and every gs c command. An event a suite registers through GearSwap's wrapped registration gets a short refresh if the last refresh was 0.05 to 0.5 seconds before, a full one if it was longer, and none inside 0.05 seconds.

      Why the suites differ.

      Cause 2

      GearSwap's walk around every event

      Around every event it runs for a suite, GearSwap reads the gear the character wears and then matches what the handler proposed against what the character carries in the equippable bags: the inventory and eight wardrobes, 720 rows in all. Both 0.940 versions walk every row, even when the handler proposed nothing, and the walk is the same code in both. GearswapRevised keeps an index of those bags by item name, so an event visits only the rows holding the items its handler named, in the order the full walk would reach them.

      How this was measured

      The versions
      GearSwap's work
      What runs
      Each suite's complete shipped code, compiled into a per-client sandbox in GearSwap's own load order. Each of the two Mirdain-lineage trees runs with the job files and gear library it carries. Selindrile runs its full library chain with its bundled organizer include. Registrations, schedules and settings run as shipped. Nothing is extracted or paraphrased.
      States
      Lean is every chat channel off, Hoxne off and Treasure Hunter None, every lock at its load default. For Selindrile this is the parity tier, with its Bard's weapons held through songs as the 1.5.12 source holds them. Moderate is each suite's own first-load defaults plus the modes this party plays: Hoxne on the Bard where the engine has the mode (Rahvin GS 2.1), Treasure Hunter Tag on the Corsair on all three, and the Bard's weapon lock on Songs where the engine has that mode (Rahvin GS 2.1), as Rahvin plays it. For Selindrile this is the practical tier, its Bard's weapon set freed for songs.
      Gear
      The same six loadouts everywhere, but each lineage engine brings its own copy of them. Rahvin GS 2.1 runs the job files and gear library it carries. 1.5.12 runs those files as a later Mirdain-named release shipped them, the set this comparison has loaded under it since its first run; it cannot load 2.1's, which call engine hooks it does not have. So the pair differs by a whole tree, not by an engine file alone. Selindrile runs generated ports of the same six loadouts, each wearing its source's weapons, with every set checked against the original. Selindrile's upstream files stay pinned byte for byte.
      Timing
      Unit costs come from continuous hot loops of 250 ms or more, on the real clock, outside the sandbox. Inside it, time is virtual and driver-controlled, so busy windows, throttles and item cooldowns all run on their true cadence. The measurement ran pinned to one processor at high priority on an otherwise quiet machine.

      Where these numbers can mislead

      The versions compare only past the drift between sessions.

      One part of GearSwap is priced in no version.

      GearSwap's prices are Rahvin's characters'. The rates were recorded at a busy camp, not in a Divergence wave, and the alliance's other twelve members are added to each refresh by inference.

      The suites' own code weighs more under GearswapRevised.

      What the plus or minus covers.

      The two lineage columns are whole trees of different ages, not engine files. Rahvin GS 2.1 is measured as it ships, with engine, gear library and job files together. 1.5.12 runs the job files as a later Mirdain-named release shipped them. So the gap between those two columns is what a player moving from the original include to this suite would see, and it is not purely the engine. No arrangement isolates the engine and stays realistic, so the realistic one is reported.

      The suites draw the automation boundary in different places. Selindrile bundles play automation into the measured suite. The Mirdain-lineage engines are designed as the gear-swap layer of a setup where sequencing, if automated at all, runs outside GearSwap, where no column here can see it. A moderate-state gap between them is partly a boundary difference. The lean and parity columns are less affected, because optional automation is off there, with one stated exception: Rahvin GS's received-spell system keeps its shipped default, so its lean column carries a subsystem 1.5.12 does not have.

      Selindrile is measured at its pinned upstream commit of 2026-07-23, on ported gear, with its shipped defaults. Claims about Selindrile are claims about that version on this scenario and nothing broader. Selindrile's measured columns exist because its library genuinely boots, casts, equips and tracks here, verified end to end before any number was recorded.
